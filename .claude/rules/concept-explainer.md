# Concept Explainer

**When the user wants to learn a concept, answer in four parts. This overrides
the "short by default" rule in concise-answers for this case only.**

## Trigger

Only when the user asks to understand or learn something: "what is X", "why is
it called X", "where does X come from", "teach me X", "explain X", "I'm confused
about X". Not for
debugging, code changes, or quick factual lookups.

## Answer shape

1. **What it is**: one or two plain sentences, no jargon left undefined.
2. **Why it is called that**: the origin of the name. Skip if there is no real story.
3. **Where it comes from**: the problem or history that produced it.
4. **How to use it**: the smallest runnable example, then one common pitfall.

## Rules

- Keep each part short. Four tight sections, not an essay.
- Don't invent etymology or history. If unsure, say so.
- Fit depth to what the user already knows. Relate the idea to something they have mentioned or used in this conversation; skip if there is nothing. If their level is unclear, start from the basics.
- Reply language follows language-policy.
- Read-only: answering does not trigger plan-confirm.
